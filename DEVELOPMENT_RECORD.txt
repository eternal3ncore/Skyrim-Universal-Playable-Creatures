UNIVERSAL PLAYABLE CREATURES
CHRONOLOGICAL DEVELOPMENT / RESEARCH RECORD
Merged line created: 2026-08-31

PURPOSE
=======
This record preserves the implementation lineage, confirmed behavior, merge decisions,
and rollback rules for Universal Playable Creatures (UPC) after incorporation of the
Universal Creature Controls (UCC) runtime core.

BASELINES AT MERGE
==================
- UPC v0.1.6 is the pre-merge playability/support baseline.
- UCC v2.45 is the canonical historically confirmed controls baseline; later work
  carries forward only deliberately retained, tested/event-driven improvements.
- The first merged candidate is UPC v0.2.0. It is NOT a new stable baseline until
  it is tested in Skyrim by the user.

PROJECT OWNERSHIP DECISION — 2026-08-31
======================================
The merged project lives under Universal Playable Creatures. UPC owns the public
SKSE identity and includes the controls/runtime adaptations needed to use supported
creature races as the player.

Runtime target:
  Data\SKSE\Plugins\UniversalPlayableCreatures.dll
  Data\SKSE\Plugins\UniversalPlayableCreatures.json
  Data\SKSE\Plugins\UniversalPlayableCreatures\*.json race catalogs

There is one SKSE entry point, one SKSE initialization, one default log, and one
owner for each runtime feature. A separately installed UCC DLL must not be used
alongside the merged UPC DLL.

MERGE SAFETY / CLEANUP RULES
============================
1. Preserve established UCC combat/crafting/casting behavior during the structural merge.
2. Preserve UPC RaceMenu and camera behavior without combining unrelated logic.
3. No polling loops, worker timers, delayed retries, input replay, or save-baked state.
4. No SKSE serialization.
5. Duplicate implementations are removed rather than left dormant. The evolved UCC
   weapon-visual path is authoritative; UPC's older WeaponHide namespace, ActionEvent
   sink, clone-culling state, and related load/race synchronization were physically removed.
6. The obsolete UPC playableRaces parser and its JSONC string-array helper were removed;
   RaceCatalog v2 is the sole race-catalog implementation.
7. Converted physical attacks retain real BGSAttackData lifetime and authored HitFrame
   behavior; physical attackData is not cleared at HitFrame itself.
8. Werewolf, Vampire Lord, and Werebear keep their vanilla/vanilla-derived behavior
   systems; existing crafting interception is the retained historical exception.
9. A successful compile is necessary but not sufficient for stable status; runtime
   validation remains required.

RACE CATALOG SCHEMA — 2026-08-31
================================
Canonical object row:

  {
    "race": "Plugin.esm|FORMID",
    "playable": false,
    "spellHand": "Left"
  }

The root array is "races". playable and spellHand are independent. Catalog loading
is namespaced, non-recursive, sorted/deterministic, and isolates invalid/unresolved rows.

Known packaged catalog counts:
- Skyrim/Dawnguard/Dragonborn: 122
- Oblivion: 223
- Morroblivion: 68
- Total: 413

SPELL HANDEDNESS RESEARCH — OBLIVION
====================================
Converted Oblivion policy from converter/action evidence:
- native cast + no block: Left
- native cast + block: Right
- fallback/non-native + no block: Left
- fallback/non-native + block: Right
- runtime-confirmed evidence overrides static routing.

Anchors:
- Scamp: Left.
- Minotaur: Right, runtime-confirmed.
- Xivilai: Left, runtime-confirmed exception to static Right prediction.
- Clannfear: current fallback Right because converter metadata reports block=true;
  future runtime evidence may override it.

Corrected Oblivion mapping: 84 Left / 139 Right across 223 rows, no None values.

SPELL HANDEDNESS RESEARCH — SKYRIM
==================================
The user supplied a 660-file Skyrim/DLC behavior corpus on 2026-08-31. A first-pass
BeginCast marker audit found multiple creature behavior files with BeginCastLeft and
no BeginCastRight, and no right-only BeginCast behavior in the scanned set. Other
families expose both generic lanes; both-lane bridge symbols are not sufficient to
classify a race as Both.

Decision: all 122 packaged Skyrim/Dawnguard/Dragonborn creature rows default to
spellHand=Left. Precedence is runtime-confirmed override, then strong behavior/action
routing, then the Left default. See SKYRIM_HANDEDNESS_AUDIT.md.

MERGED MODULE OWNERSHIP — UPC v0.2.0
====================================
UPC host owns:
- SKSEPluginInfo / SKSEPluginLoad / SKSE::Init
- UniversalPlayableCreatures.log
- UPC base-config parsing
- RaceMenu safeguards
- RaceCatalog v2 loading/playable flag application
- Camera3rd node utility
- runtime spell equip-side restriction

UCC internal core owns:
- attack-data discovery and attack dispatch
- normal/power attack routing and blocking bridge
- spell/shout fallback execution and HitFrame synchronization
- crafting/workbench interception
- traversal/collision fallback
- authoritative weapon visual handling

The UCC core is now vendored as src/ucc_core.cpp. It has no second SKSE export and
uses the UPC logger/config namespace. The final build no longer checks out the UCC
repository or generates merged source during CI after the one-time cleanup commit.

BUILD VALIDATION — 2026-08-31
=============================
An earlier merged build passed Windows CI before final dead-code cleanup. The final
self-contained workflow validates:
- vendored src/ucc_core.cpp exists
- exactly one SKSEPluginLoad source entry exists
- known obsolete UPC WeaponHide/parser symbols are absent from src/plugin.cpp
- Release configuration compiles on Windows
- UniversalPlayableCreatures.dll is produced
- exactly one SKSEPlugin_Load DLL export exists when dumpbin is available
- the v0.2.0 test artifact contains source, config, catalogs, DLL, and research record.

ROLLBACK / RELEASE DISCIPLINE
=============================
Do not promote UPC v0.2.0 to stable until it is tested in Skyrim. If the candidate
fails, isolate the merge-specific regression rather than rewriting established UCC
or UPC systems broadly.
