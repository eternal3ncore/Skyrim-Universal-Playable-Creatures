UNIVERSAL PLAYABLE CREATURES
CHRONOLOGICAL DEVELOPMENT / RESEARCH RECORD
Merged line created: 2026-08-31

PURPOSE
=======
This record preserves the implementation lineage, confirmed behavior, merge decisions,
and rollback rules for Universal Playable Creatures (UPC) after incorporation of the
Universal Creature Controls (UCC) runtime core.

BASELINES AT MERGE
==================
- UPC v0.1.6 is the pre-merge playability/support baseline.
- UCC v2.45 is the canonical historically confirmed controls baseline; later work
  carries forward only deliberately retained, tested/event-driven improvements.
- The first merged candidate is UPC v0.2.0. It is NOT a new stable baseline until
  it is tested in Skyrim by the user.

PROJECT OWNERSHIP DECISION — 2026-08-31
======================================
The merged project lives under Universal Playable Creatures. UPC owns the public
SKSE identity and includes the controls/runtime adaptations needed to use supported
creature races as the player.

Runtime target:
  Data\SKSE\Plugins\UniversalPlayableCreatures.dll
  Data\SKSE\Plugins\UniversalPlayableCreatures.json
  Data\SKSE\Plugins\UniversalPlayableCreatures\*.json race catalogs

There is one SKSE entry point, one SKSE initialization, one default log, and one
owner for each runtime feature. A separately installed UCC DLL must not be used
alongside the merged UPC DLL.

MERGE SAFETY / CLEANUP RULES
============================
1. Preserve established UCC combat/crafting/casting behavior during the structural merge.
2. Preserve UPC RaceMenu and camera behavior without combining unrelated logic.
3. No polling loops, worker timers, delayed retries, input replay, or save-baked state.
4. No SKSE serialization.
5. Duplicate implementations are removed rather than left dormant. The evolved UCC
   weapon-visual path is authoritative; UPC's older WeaponHide namespace, ActionEvent
   sink, clone-culling state, and related load/race synchronization were physically removed.
6. The obsolete UPC playableRaces parser and its JSONC string-array helper were removed;
   RaceCatalog v2 is the sole race-catalog implementation.
7. Converted physical attacks retain real BGSAttackData lifetime and authored HitFrame
   behavior; physical attackData is not cleared at HitFrame itself.
8. Werewolf, Vampire Lord, and Werebear keep their vanilla/vanilla-derived behavior
   systems; existing crafting interception is the retained historical exception.
9. A successful compile is necessary but not sufficient for stable status; runtime
   validation remains required.

MERGE POLISH / INPUT REGRESSION FIX — UPC v0.2.1 CANDIDATE — 2026-08-31
=======================================================================
Runtime testing of merged v0.2.0 established that UPC host features loaded correctly
(catalogs, RaceMenu protection, camera, spell-hand orientation) while all UCC input
commands were silent. Force-sheathe produced no diagnostic, and attacks/control
commands likewise failed to enter the UCC path.

Root cause:
- The merged DLL registered UPC::MessageHandler first, then UCCCore attempted a second
  SKSE RegisterListener callback for the same plugin handle and the same SKSE sender.
- SKSE treats a plugin already registered for that sender as registered and returns
  success without adding a second callback. UCC therefore believed initialization had
  succeeded, but its lifecycle handler never received kInputLoaded/kDataLoaded/etc.
- Because UCC's kInputLoaded handler never ran, its BSInputDeviceManager InputSink was
  never installed. This disabled every input-driven UCC feature at once.

v0.2.1 merge architecture:
1. Exactly one SKSE messaging listener remains: the UPC host MessageHandler.
2. UCCCore no longer calls SKSE::MessagingInterface::RegisterListener.
3. UPC forwards lifecycle messages into UCCCore::HandleSKSEMessage after host-owned
   state is prepared. On kDataLoaded this means config and RaceCatalog are ready before
   UCC performs creature classification/capability discovery.
4. Exactly one BSInputDeviceManager sink remains. UPC EventRouter receives the input
   chain and forwards it to UCCCore::ProcessInputEvents, then performs the independent
   camera POV check on the same chain.
5. Exactly one MenuOpenClose sink remains. UPC EventRouter forwards CraftingMenu events
   to UCCCore instead of registering a second UCC UI sink.
6. RaceSwitchComplete now explicitly refreshes UCC state in the shared EventRouter.
   The existing input-time race-ID fast path remains only as a cheap safety net for
   unusual race changes and does no per-frame work.
7. UCC's private second config-file parse was removed. UPC parses the shared config
   once with nlohmann::json and passes weapon-visibility settings to UCCCore.
8. UCC's redundant private logger setup and standalone include/config scaffolding were
   removed. The internal core now uses the host PCH/logger/config ownership.
9. RaceCatalog now retains an enabled-race set. `playable=true` is the authoritative
   UPC/UCC availability switch for ordinary catalog creatures; `playable=false` rows
   may still carry independent metadata such as spellHand. Werewolf/Vampire Lord/
   Werebear retain the historical crafting-only exception.
10. Duplicate catalog rows are deterministic: a later resolved row replaces prior
    availability and hand metadata, with a warning.
11. Human-readable catalog metadata (`name`, `editorID`) is intentionally ignored by
    the parser and is safe to ship for maintenance/readability.
12. The build script now stages the newly compiled DLL into
    runtime\Data\SKSE\Plugins\UniversalPlayableCreatures.dll and the package omits the
    stale v0.2.0 DLL before compilation.

Runtime validation required before commit/stable promotion:
- Log must show `Shared UPC/UCC input event routing registered` at InputLoaded.
- Log must show `UCC lifecycle: InputLoaded (shared input route ready)`.
- On Scamp load with playable=true, UCC must log UniversalCreature policy with
  catalogEnabled=true and discover the race attack capability profile.
- Normal attack, Sneak power attack, Jump hold/release, block, shout/spell fallback,
  and Ready Weapon+Sprint force-sheathe must again enter their established UCC paths.
- Force-sheathe must emit its `Forced sheathe chord:` diagnostic.
- A catalog race changed to playable=false must not receive UniversalCreature controls.
- Scamp Left-hand spell orientation must remain functional and unchanged.

This v0.2.1 package is an experimental test candidate only. No repository commit should
be made until the user confirms the merged control path and catalog gating in-game.


NATIVE-FIRST SPELL OWNERSHIP — UPC v0.2.3 CANDIDATE — 2026-08-31
=================================================================
Runtime validation of v0.2.1 confirmed the merged lifecycle/input repair and showed
converted Scamp left-hand spell input reaching the correct visible spell animation.
However, UCC simultaneously executed its manual immediate cast on button release,
which launched the spell before the authored animation reached its native release point.

Root cause:
- Fire-and-forget input always entered the UCC fallback backend on release.
- The fallback decision did not first test whether Skyrim's native hand MagicCaster had
  already accepted/owned the exact spell from the preceding DOWN input.
- Animation-graph event return values are not a reliable substitute for caster ownership;
  the Scamp visibly entered its correct spell animation even while the old fallback path
  reported an animationless immediate cast.

v0.2.3 correction:
1. DOWN records only the spell, hand, and press time and clears stale UCC fallback state.
   It does not take MagicCaster ownership or start a competing spell visual.
2. On UP, UCC checks the matching hand MagicCaster. If `currentSpell` is the exact
   equipped spell, native ownership is confirmed and UCC performs no cast, no fallback
   animation, and no launch-time substitution. Skyrim/behavior owns release timing.
3. Only when native ownership is absent does UCC enforce the native charge duration,
   run CheckCast, and enter compatibility fallback.
4. If the fallback animation is accepted, the spell payload is queued for the exact
   animation HitFrame through the existing CreatureAnimationEventSink.
5. Only the absolute bottom fallback (no native owner and no accepted fallback animation)
   uses CastSpellImmediate, explicitly logged as animationless bottom fallback.
6. Self-delivery concentration behavior is intentionally unchanged in this candidate;
   this change is narrowly scoped to fire-and-forget/fixed-duration casting.

Validation targets:
- Scamp log should show `spell native ownership CONFIRMED` and should NOT show
  `immediate spell cast` or `spell FALLBACK` for a working native cast.
- Scamp projectile/effect should launch at the authored animation's native timing.
- A creature lacking native spell ownership should log `spell FALLBACK`; if its fallback
  animation is accepted, the spell should fire only at exact HitFrame.
- Existing attack, block, Sneak power attack, Jump, force-sheathe, catalog gating, and
  spell-hand restriction behavior should remain unchanged.

This remains an experimental test candidate. Do not promote or commit as stable until
runtime validation confirms native and fallback spell paths separately.


2026-08-31 - v0.2.3 hand-equip drawn-state preservation candidate
- Added TESEquipEvent to the existing shared UPC event router; no new independent SKSE lifecycle/input listener.
- For active UniversalCreature players, successful EQUIP events are filtered to hand equipment only: weapons, spells, torches/lights, and shield-slot armor. Ordinary armor/clothing/jewelry is ignored.
- If the player is already drawn when hand equipment becomes equipped (Inventory, Magic, Favorites, hotkey, or other source), UPC invokes the existing force-sheathe path once and records that the pre-change state was drawn.
- Redraw is event-driven: preferred completion is SKSE ActionEvent kEndSheathe; NiNodeUpdateEvent is a secondary graph/3D completion point. No timers, frame polling, save serialization, or menu qualifiers.
- Internal force-sheathe recovery equip operations are guarded against recursively starting another hand-equip transaction.
- Auto-redraw will not force through an active left/right native MagicCaster; native-first spellcasting remains authoritative.
- Leaving UniversalCreature policy clears any pending hand-equip transaction.
- Diagnostic lines: `Hand-equip while drawn...` and `Hand-equip drawn state RESTORE...`.
- Test candidate only; no stable checkpoint/commit until in-game validation.

2026-08-31 - v0.2.4 native hand-equip interception candidate
- v0.2.3 runtime test proved TESEquipEvent is not emitted reliably for the player hand changes UPC must observe. The shared event sink registered, but no hand-equip callback occurred during tested spell/equipment changes.
- Removed TESEquipEvent routing and the dead ProcessEquipEvent path rather than retaining duplicate mechanisms.
- Added MinHook-based interception of the two authoritative Skyrim equipment entry points exposed by CommonLibSSE-NG/Address Library:
  * ActorEquipManager::EquipObject (weapons, shields, torches/hand objects)
  * ActorEquipManager::EquipSpell (spells)
- Interception is player-only, UPC UniversalCreature-only, drawn-state-only, and filters to hand-capable forms. Ordinary armor/clothing/jewelry is ignored; armor only qualifies when it occupies the shield slot.
- The pre-equip drawn state is captured at the native equipment boundary. UPC invokes the established force-sheathe path before the requested native equip proceeds. Re-entrant equipment calls made by force-sheathe recovery are guarded and pass directly through to Skyrim.
- After Skyrim's original EquipObject/EquipSpell call returns, UPC restores the prior drawn state once. EndSheathe remains a valid earlier completion point if Skyrim emits it; otherwise the post-native-equip return is the deterministic one-shot completion point. No polling, timer, menu qualifier, hotkey qualifier, or save state is used.
- Native spellcasting v0.2.2 behavior is otherwise unchanged. Automatic redraw refuses to force through an active native MagicCaster.
- MinHook is now a vcpkg dependency. Hooks are enabled individually; UPC does not globally enable/disable hooks belonging to other plugins.

2026-08-31 - v0.2.7 pre-menu hand snapshot / deferred post-menu transaction
- v0.2.6 did not reliably preserve drawn state because it depended on a rolling observed-hand baseline at menu-close time. That baseline could already reflect menu-time state and did not preserve the authoritative pre-menu drawn condition.

- Menu CLOSE performs no actor/equipment manipulation inside the UI callback. It queues exactly one SKSE game task; that task compares PlayerCharacter::GetEquippedObject(left/right) against the pre-menu snapshot after the menu callback has fully unwound.

- Numbered/direct hotkeys use the same transaction principle: snapshot on the Hotkey input DOWN edge while no equipment menu is open, then compare once on a queued game task after input processing. Favorites-menu opening itself is not treated as a hotkey transaction; Favorites selection is handled by its menu snapshot.
- Removed the v0.2.6 rolling observed-hand state, menu-close observer, and end-draw/end-sheathe observation duplication. EndSheathe remains a completion signal for an already pending redraw.

2026-08-31 - v0.2.12 TESEquipEvent correction / single equipment notification source
- Re-examination of the actual v0.2.3 source invalidated the earlier conclusion that TESEquipEvent was unreliable. The v0.2.3 handler returned on `!player->IsWeaponDrawn()` before emitting its `Hand-equip while drawn` diagnostic; later runtime testing established that `IsWeaponDrawn()` can be false for visibly drawn/ready converted creatures. Therefore absence of that diagnostic did not prove absence of TESEquipEvent.
- Restored TESEquipEvent to the existing shared UPC EventRouter through ScriptEventSourceHolder. No second SKSE lifecycle/input listener was added.
- The raw event is logged before actor/policy/menu filtering: `TESEquipEvent: actor=... form=... equipped=...`. This first diagnostic candidate is intended to answer definitively whether tested spell/weapon assignments emit the event.

- Outside equipment menus, a player UniversalCreature TESEquipEvent queues exactly one SKSE task. Multiple events coalesce while a check is queued.
- Inventory, Magic, and Favorites remain safety gates only. A TESEquipEvent received while one is open sets `equipmentCheckPending=true` and does not manipulate the actor. Menu close queues the same one-shot settled-hand comparison used outside menus. There is still only one equipment notification source.

- Removed NiNodeUpdateEvent from hand-equipment detection. NiNodeUpdateEvent remains registered solely for existing weapon-visual resynchronization.
